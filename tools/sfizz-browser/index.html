Experimental standalone proof of concept

sfizz + VSCO in the browser

Select a local VSCO Community Edition folder. The app reads only the selected patch and referenced WAV files through browser local-file APIs, transfers those bytes into an sfizz AudioWorklet, writes them into sfizz's in-memory Emscripten filesystem, and plays with upstream sfizz WebAssembly. No files are uploaded and no sample library files are copied into this repository.

Browser support: Chromium/Edge can use the folder picker. Automated checks use the fallback directory input.

2. Load one SFZ patch

sfizz-webaudio is built without disk streaming. The cap above covers raw selected WAV bytes before transfer; it is not a total browser or WASM heap cap. Patch loading happens inside the audio thread, so switching is experimental and not seamless.

Select a library folder first.

3. Play notes / real-time AudioWorklet

CC11 changes expression during playback. CC1 behavior depends on the patch; VSCO's supplied mappings do not define dynamic-layer crossfades. Each Play replaces the previous phrase. MIDI note names use C4 = 60.

Load a patch before playback.
