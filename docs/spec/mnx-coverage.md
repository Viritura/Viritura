# MNX Spec Coverage & Viritura Feature Gaps

This document tracks which standard music notation features are covered by the
W3C MNX specification and which are NOT, informing what Viritura can offer as
editable notation vs. rendering-only or deferred.

> **Baseline:** MNX schema 34 (2026-08-25). Schema 34 permits fractional
> `bpm` values; Viritura preserves them through parsing, authoring, engraving,
> playback, MusicXML import, and picture fitting. The earlier schema 27 update
> restructured accent dynamics, widened the dynamic range, extended dynamic
> groups, and introduced the `measure-repeat` (simile) object; bundled `.mnx`
> fixtures were migrated by
> [`scripts/migrate-mnx-v27-dynamics.mjs`](../../scripts/migrate-mnx-v27-dynamics.mjs).
> See [`dynamics.md`](dynamics.md) for the full dynamic-group model.

## Features NOT in MNX Spec (stored via `_x.viritura` vendor extensions)

These features are universally expected in modern engraving but have
**no representation in the current MNX spec**. Viritura stores them using the
MNX-standard `_x.viritura` vendor extension mechanism directly in the `.mnx` file.
See [viritura-extensions.md](./viritura-extensions.md) for the complete schema.

**Status:** All features below are implemented in the rendering engine and stored
using `_x.viritura` vendor extensions that pass MNX JSON Schema validation.

## MNX Spec Features NOT Yet Implemented

These are standard MNX spec features Viritura does not yet render or test:

| Feature                                            | MNX Object                                                | Status                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Drum kit notation**                              | `kit-component`, `kit-note`, `sound` (in `global.sounds`) | ✅ Implemented — model + parser/serializer, percussion clef, kit-note layout (uses `staffPosition`, no accidentals), notehead shape via `_x.viritura.notehead` (MNX gap [#249](https://github.com/w3c/mnx/issues/249)), GM channel-9 playback, shared percussion-map editor for score creation and existing parts, and Storybook stories. |
| **Layout changes (per-system)**                    | `system.layout`, derived layouts                          | ✅ Authored via Engrave Mode (`setStaffVisibilityInScore`); engine swaps layout per system.                                                                                                                                                                                                                                               |
| **Layout changes (mid-system)**                    | `layout-change`                                           | ⚠️ Parsed and applied for staff swaps only — staff-count reductions mid-system not yet supported (use a system break instead).                                                                                                                                                                                                            |
| **Page object** (system grouping into pages)       | `page`                                                    | ✅ Authored via Engrave Mode forced page breaks. Page size/margins remain engine render config (`page_width`, `page_margin_*` in `LayoutConfig`, surfaced as per-score `pageSetup` vendor ext).                                                                                                                                           |
| **Compound time signature display** (e.g. `3+2/8`) | Not in MNX spec                                           | ⚠️ MNX `time-signature-display` only supports `"common"` and `"cut"` — no additive/compound form. This is a spec gap, not a Viritura gap. Would need `_x.viritura` extension.                                                                                                                                                             |
| **Performance metadata**                           | `perform-options`                                         | ⚠️ Round-tripped on kit-notes, but not yet acted on (the MNX spec currently defines it as a stub).                                                                                                                                                                                                                                        |

## Storybook Coverage Audit

All 71 upstream official MNX example files in `packages/format/fixtures/mnx/` have a
matching story under `apps/editor/src/stories/mnx-spec/`. The folder also contains
15 locally-authored fixtures (sample scores, condensing tests, and video-sync cues) that
are not part of the upstream W3C MNX examples but do pass the same schema-validation suite. Beyond the
example-driven stories, dedicated stories exist for accidental display,
articulations (incl. stress/unstress/softAccent/spiccato/staccatissimo),
tuplet-display, time-signature-display (common/cut), staff-group brackets/
braces/no-symbol/nested, transposition, cross-staff, custom SMuFL glyphs,
ottava, multimeasure rests, repeats with alternate endings, jumps, barline
styles, clef changes, and key signatures.

**Storybook gaps** remaining: none for MNX standard objects — drum kit (`kit-component`/`kit-note`) is now covered by `DrumKit.stories.tsx` (BasicKit + NoteheadShapes). Compound time signatures are not in the MNX spec (only `common`/`cut` glyphs) — would need a `_x.viritura` extension if desired. `layout-change`, `page`, and per-system staff visibility are now covered by the _Engrave Mode_ stories (`Forced Breaks`, `Staff Visibility`, `Condensing`).
